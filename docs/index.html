Overview

Helios Gateway is a cloud-native GraphQL federation gateway. It gives clients one GraphQL endpoint while the platform can keep domain logic split across independently deployed subgraph services.

The gateway discovers subgraphs, composes the federated schema, verifies Firebase identity tokens, applies role-based access control from the composed schema, and exposes an admin console for day-to-day operations.

Clients Applications call a single GraphQL endpoint.
Helios Gateway Composes schema, verifies auth, enforces RBAC, and routes operations.
Auth Provider Firebase Authentication issues and verifies identity tokens.
GraphQL requests flow through the gateway to discovered subgraphs
Orders Subgraph Owns order types, fields, and resolvers.
Customers Subgraph Owns customer data and account relationships.
Pets Subgraph Owns catalog and pet-shop domain fields.

Main Idea

Helios Gateway is meant to be the operational front door for a federated GraphQL platform. Subgraphs can move between local Docker, static file configuration, and Google Cloud Run without changing how clients talk to the graph.

Discovery is intentionally environment-driven. In local demos, Docker labels or a YAML file describe subgraphs. In Cloud Run, service labels identify subgraphs and optional graph scope. The gateway uses that discovered service list to build and refresh the composed schema.
